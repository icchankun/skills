# writing-notion-docs

会話で決めたことや調べた結果を、Notion のページに書く。読むのは、あとでそのページを開くチームの人で、この会話は持っていない。

使える Notion の連携（MCP など）で、ページを読み書きする。使えなければ、書く文を Notion の書式で返し、ユーザーに貼ってもらう。

## 1. 書く場所を決める

- ユーザーがページか節（URL の `#` 以降）を示したら、そこに書く。節の指定があれば、その節の下に足す。
- ページだけ示されたら、ページを読んで、内容が合う既存の節を探す。合う節がなければ、新しい節をページの末尾に足す。
- どこにも示されていなければ、関係するタスクやページを Notion で探し、候補を1〜2個挙げて、どこに書くかを聞く。

書く前に、そのページをいちど全部読む。同じことを書いた節がすでにあれば、新しい節を作らず、その節を直す。同じ中身の節が2つ並ぶと、どちらが正しいか分からなくなるため。

## 2. 下書きを書く

- 結論を先に書く。調べた結果なら「何が分かったか」、方針なら「どうするか」から始める。
- 手順や確かめることは、チェックリスト（`- [ ]`）にする。1項目に1つの作業を、そのまま実行できる粒度で書く。
- 作業を段階に分けるときは、「STEP 1」のように番号を振り、それぞれに、やることと終わる条件を書く。
- 分岐・状態の移り変わり・構成は図にする。図の決まりは reviewing-writing の `references/diagrams.md` に従う。
- 数値は元にした資料（artifact・クエリの結果・PR など）の値をそのまま書き、出どころへのリンクを添える。資料が複数あって値が食い違うときは、書く前にどれに合わせるかをユーザーに聞く。
- タスクやページの題名は、何をするかが題名だけで分かる具体的な文にする（「README の修正」ではなく「README のインストール手順を apm に合わせて書き直す」）。
## 3. 見直す

`reviewing-writing` で見直す。渡すときに、文章の種類が Notion のページで、チェックリストと STEP の見出しはこの skill が決めた書式なので残すよう書き添える。

## 4. 見せて書き込む

書く場所と、見直した下書きを見せて確認を取る。直すよう言われたら、直したものをもう一度見せる。OK が出てから書き込む。

書き込んだら、ページの URL（節に足したなら、その節へのリンク）を伝える。

## 規律

- ほかの人が書いた節は、頼まれない限り書き換えない。足すだけにする。
- ページやタスクの状態（完了など）は、頼まれたときだけ変える。
