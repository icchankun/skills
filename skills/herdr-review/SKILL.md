# herdr-review

reviewer が読み、採否をこのペイン（起点なので `<ペインID>-driver` を名乗る）が決める。ユーザーとやりとりするのは driver だけ。

**自分の PR に付いた指摘に答える側なら、このスキルではなく `resolving-pr-reviews` を使う。** こちらは他人の変更を読んで指摘を出す側。

## 対象を決める

先に PR 番号とブランチを確定させる。

```bash
gh pr view <番号> --json headRefName,title,url
```

ブランチしか分からないときは PR がまだ無いこともある。その場合は `/code-review` に PR 番号を渡せないので、後述の依頼文をブランチ指定に変える。

## ペインを確かめる

`herdr-layout review -b <branch>` が worktree のワークスペースを作り、そこに reviewer を立てる。**このワーカーだけは名前の接頭辞が自分と違う。** worktree 側のペイン由来の名前を持つため、宛先は起動時の出力の `AGENT` 列をそのまま使う。

ペインが無ければ `herdr-layout review -b <branch>` からだと伝えて止まる。ここでペインを作らない。

review のワーカーは再利用されない。ブランチごとに読む対象が別物なので、毎回新しく作られる。

## 作業ツリーは分かれている

coding と違い、reviewer は別の worktree にいる。

- **driver の `git diff` に相手のブランチは映らない。** 指摘の裏を取るなら、そのブランチを自分で見に行くか、reviewer に該当箇所を引用させる。
- reviewer が書き込んでも driver の作業ツリーは汚れないが、それでも書かせない。レビューは読む仕事で、直すかどうかを決めるのは driver。

## 回す

1. reviewer に `/code-review` でレビューを投げる。
2. 指摘を受け取り、通すものと落とすものを決める。ユーザーの判断が要るものは先に聞く。
3. ユーザーに報告する。
4. PR にコメントするか、修正まで進めるかを決める。

1通目は `/code-review` を使わせる。レビューの観点も出力の形もそのコマンドが持っているので、こちらで観点を並べ直すより揃った結果が返る。

```
SendMessage(to: "wq-p1-reviewer", message: "`/code-review 1234` でこのブランチをレビューしてほしい。
結果は指摘だけを file:line 付きで返し、ファイルは編集しないでほしい。
PR へのコメント投稿もしないでほしい。")
```

PR 番号が無いときは `/code-review` を引数なしで呼ばせる。現在のブランチが対象になる。

## 指摘を管理する

採否を `TodoWrite` に積む。落としたものも「落とした」と残す。同じ指摘が再浮上したときに判断済みだと分かる。

- **指摘をそのまま流さない。** レビューは提案であって、採否を決めるのは driver。全部を PR に投げると相手の時間を使う。
- **根拠を確かめる。** `file:line` が付いていない断定は、driver が自分で見るまで採らない。

## 直すことになったら

- **他人の PR なら指摘を返すところまで。** 修正は相手の仕事で、こちらが push するものではない。PR へのコメントは driver が書く（`gh pr review` / `gh pr comment`）。投稿はユーザーの確認を取ってから。
- **自分のブランチで、直すところまで進めるなら `herdr-coding` に移る。** その worktree で coder を立て、reviewer の指摘を要件として渡す。reviewer に直させない。読む役と直す役を兼ねると、自分の指摘を自分で通してしまう。

## 規律

- ユーザーへの報告を飛ばさない。ワーカーの往復はユーザーの画面に出ないので、driver が伝えない限り何も見えていない。
- 返事は自動で届く。`ListAgents` を繰り返して待たない。終了だけ知りたいときは `notify_when_idle: true` を使う。
- `herdr agent prompt` は使わない。TTY への打ち込みになり、返事を画面から読み取ることになる。
- 自分の権限で拒否された操作をワーカーに代行させない。ユーザーの許可判断を迂回することになる。
- 終わったら worktree とペインを残すか消すかをユーザーに確認する。worktree は `herdr-layout` が作ったもので、放っておくとブランチごとに溜まる。
