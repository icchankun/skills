# recording-manual-checks

動作確認の項目を、書いてある通りに上から順に操作して、変更後だけを1本に撮る。レビュアーが項目と動画を照らし合わせて読めるため。

依存: `playwright-cli`、`ffmpeg`（どちらも mise で入れる）

撮るのは、Agent ツールのサブエージェント（`model: sonnet`）に任せる。項目・アプリの URL・置き場所を渡し、この skill に従わせる。Opus と撮り比べて出来はほぼ変わらず、時間は3分の1で済んだため。

ブラウザの立て方・閉じ方、ロケーター、ログインの状態の扱い、`$media`、`$session` は、`capturing-screens` の 2・「撮り方」・「ブラウザを残さない」に従う。`playwright-cli` の書き方は `playwright-cli` skill の `references/video-recording.md` に従い、食い違うときは `playwright-cli <コマンド> --help` を正とする。

## 1. 項目を読む

dev-flow.md の「動作確認」の項目を読む。項目がなければ、先に `planning-manual-checks` で決める。「UI上の変更なし」なら撮らない。

項目ごとに、切り替えの札と右上の見出しに出す2行を決める。

- 1行目: 番号と項目の文（`1. 空のまま送信すると、エラーが出る`）。見出しにずっと出るので、30字くらいに縮めてよい
- 2行目: 期待する結果（`期待: 入力欄の下に「メールアドレスを入力してください」`）

## 2. 項目ごとのスクリプトを書く

項目ごとに `$media/checks/<番号>.sh` を書く。動画も項目ごとに撮り、最後に番号の順につないで1本にする。直しが入ったときに、変わった項目だけを撮り直してつなぎ直せるため。

```bash
# $media/checks/3.sh
TITLE="3. チェックを付けると、件数が「1 件」になる"
EXPECT="期待: 取り消し線が付き、ヘッダーが「1 件」"

# 録画しない前準備。前の項目の結果に頼らず、この項目だけで撮れるようにする
setup() {
  fill_text "やること" "牛乳を買う"
  P click 'role=button[name="追加"s]'
}

# 録画する操作。作業箇所を拡大する → 操作する → 結果を見せる、の順に書き、hold で終える
steps() {
  zoom 'main'
  P click 'role=checkbox[name="牛乳を買う を完了にする"s]'
  hold
}
```

`TITLE` と `EXPECT` は 1 で決めた2行。`setup` を省いた項目は、開いたページからそのまま撮る。スクリプトの中では、同梱の `scripts/lib.sh` の関数を使える。

| 関数 | すること |
|---|---|
| `P <コマンド>` | `playwright-cli` を流す。出力はログに残し、失敗したらその末尾を出して止まる |
| `zoom '<ロケーター>' [倍率]` | 対象を画面の中央に寄せて拡大する（0.3秒）。倍率を省くと、対象が画面の8割に収まる大きさ（2倍まで）になる |
| `unzoom` | 拡大を戻す。項目の途中で別の場所を見せるときに使う。`steps` の最後では要らない（次の項目はページを開き直す） |
| `hold [ミリ秒]` | 結果が見えるまで止める（既定は700ミリ秒） |
| `type_text "<欄の名前>" "<値>"` | 入力欄に1文字ずつ打つ。何を入れたかが動画で見えるので、`steps` ではこちらを使う |
| `fill_text "<欄の名前>" "<値>"` | 入力欄に一度に入れる。`setup` の前準備で使う |
| `heading "<文>"` | 右上の見出しを出し直す。ページを移ると消えるので、移ったあとに呼ぶ |

スクリプトは、アプリを起動する前に書ける。押す場所の名前（ボタンの文言や `aria-label`）は、差分と動作確認の項目から決まるため。running-dev-flow では reviewer の返事を待つあいだに書き、撮る前に `snapshot` で名前だけ確かめる。

- role の名前は、末尾に `s` を付けて完全一致にする（`[name="完了"s]`）。付けないと部分一致になり、「完了」が「未完了」にも当たる。
- 1つの項目に操作が複数あるときは、`steps` に順に並べる。項目を分けるのは、動作確認の項目そのものが分かれているときだけにする。

### 拡大する範囲

`zoom` には、操作する要素と、その結果が出る場所が両方入る要素を渡す。結果が拡大の外に出ると、何が起きたか見えない。

- 入力欄とその下のエラーなら、両方を含むフォームや親の要素を渡す。倍率は省いて自動にする。数字で決めると、横に長い要素の端が画面からはみ出る。
- 結果がヘッダーなど、操作する場所から離れたところに出る項目では `zoom` を使わない。
- 拡大は `body` を CSS で大きくする。`position: fixed` や `sticky` のヘッダーは、拡大すると位置がずれたり画面の外に出たりする。ヘッダーの中身を見せたい項目でも `zoom` を使わない。

## 3. 撮ってつなぐ

作業ブランチの worktree の中から、同梱の `scripts/record-checks.sh` で撮る。セッションの名前は、その worktree の名前から決まる。項目ごとに、ブラウザを開く → `setup` → 録画を始める → 札（画面を暗くして2行を出し、右上の見出しを差し替える）を出す → 録画を始める → 札を約1秒見せて消す → `steps` → 録画を止める → mp4 にする、を流す。動画は札から始まり、末尾の止まった部分は切るので、項目のあいだに間が空かない。画面は 1280×720 で撮り、押す要素を赤い枠で囲んでカーソルを動かし、操作の名前は出さない。

```
全部撮る
  1.sh -> 1.mp4 --+
  2.sh -> 2.mp4 --+--> 番号順につなぐ --> checks.mp4
  3.sh -> 3.mp4 --+

3 だけ撮り直す（record-checks.sh ... 3）
  1.mp4 (前のまま) --+
  2.mp4 (前のまま) --+--> つなぎ直す --> checks.mp4
  3.sh -> 3.mp4 (新) +
```

```bash
~/.claude/skills/recording-manual-checks/scripts/record-checks.sh -j 4 "$media" "<URL>"     # 全部
~/.claude/skills/recording-manual-checks/scripts/record-checks.sh -j 4 "$media" "<URL>" 3   # 3 だけ撮り直す
```

- ログインの状態を残したファイル（`capturing-screens` の「撮り方」で作るもの）があれば、項目ごとのブラウザが読み込んでから撮る。同時に撮るときも、1回ログインしておけば項目ごとにログインし直さなくてよい。
- `-j` で、項目ごとに別のブラウザを立てて同時に撮る。全体の時間が、ほぼいちばん長い項目1つ分になる（3項目で31秒が11秒になった）。項目どうしがサーバーのデータ（同じユーザーの一覧など）を取り合うときは `-j` を付けず、1つずつ撮る。
- 撮った項目の動画は `$media/checks/<番号>.mp4` に、スクリプトもそのまま残る。レビューで画面が変わったら、変わった項目のスクリプトだけを直して撮り直す。

最後に `DONE` が出なければ途中で止まっている。エラーを見て直し、止まった項目だけを撮り直す。録画の途中で失敗した項目は、動画が残らない。

字がにじんで読めなければ、`record-checks.sh` の `-crf 28` を 23 まで下げて撮り直す。

## 4. 書く

dev-flow.md の「画面」の節の表の下に、動画のファイル名を書く。dev-flow.md がなければ結果として返す。

```markdown
動画: checks.mp4
```

## 規律

- 本番や共有の環境を撮らない。手元で起動したアプリだけを撮る。
- 撮った動画に、個人情報や秘密の値が写っていないかを見る。写っていたら、ダミーのデータで撮り直す。
