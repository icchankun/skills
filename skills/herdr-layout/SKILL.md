# herdr-layout

`~/.bin/herdr-layout` がペインの分割と agent の起動をまとめて行う。ワーカーは `-n <agent名>` 付きで起動するので、**Herdr の agent 名と Claude のセッション名が一致する**。起動後は `SendMessage` にその名前を渡して指示する。

名前は `herdr-agent-name` が決める `<起点ペインID>-<役割>`。ワーカーは自分のペインではなく、**立てた driver のペイン**から名前を取る。`wK:p3` の driver が立てれば `wk-p3-coder` / `wk-p3-reviewer` で、実際にどのペインに座っているかは関係ない。

こうすると名前がどの driver のワーカーかを語るので、1つのワークスペースに driver が複数いても取り違えない。同じ driver が再実行したときも名前が一致するため、既存のワーカーが再利用され、ペインが二重に増えない。

手動で立ち上げたペインは `<ペインID>-driver` に改名しておく。ワーカーを立てた起点であり、ユーザーとやりとりする側だと名前で分かるようにするため。

```bash
herdr agent rename "$HERDR_PANE_ID" "$(herdr-agent-name)"
```

これが変えるのは Herdr 側の表示名だけで、Claude のセッション名（`SendMessage` の宛先）は起動時に決まっていて追随しない。ワーカーからの返信は送り主に自動で返るので、driver 側の名前が食い違っていても困らない。

まず Herdr の中で動いていることを確認する。

```bash
test "${HERDR_ENV:-}" = 1
```

失敗したら Herdr の外にいる旨を伝えて止める。ペインを作る操作は一切しない。

## モードを選ぶ

| モード | 構成 | 使いどころ |
|---|---|---|
| `coding` | `<自分のペインID>-coder` + `-reviewer` | 実装役とレビュー役を分ける |
| `research` | `<自分のペインID>-researcher-1..N` | コードベースを並列で調べる |
| `review` | worktree + そのワークスペースの `-reviewer` | PR を別ブランチでレビューする |

```bash
herdr-layout coding
herdr-layout research -n 3
herdr-layout review -b <branch>
```

- 出力の `AGENT` 列がそのまま SendMessage の宛先になる。`STATUS` は `started`（今立てた）か `reused`（既にいたので使い回した）。`reused` なら前の作業の文脈が残っているので、1通目で今回の対象を明示する。
- `coding` で立てたら、続けて `Skill(herdr-coding)` を呼ぶ。実装とレビューの往復はそちらが持つ。
- `research` で立てたら、続けて `Skill(herdr-research)` を呼ぶ。問いの分け方と、返ってきた内容のまとめ方はそちらが持つ。
- `review` で立てたら、続けて `Skill(herdr-review)` を呼ぶ。依頼の出し方と指摘の採否はそちらが持つ。
- ワーカーは Claude を MCP 無効で起動する。ツール定義が毎リクエスト再送され、費用が並列数の分だけ掛かるため。
- ワーカーは通知も切って起動する。ユーザーとやりとりするのは driver だけなので、ワーカーが手を空けたことで中断させない。
- どのモードもタブを自分が立てたペインだけにする。それ以外は閉じるが、作業中のものは閉じずに `kept (working)` として報告する。対象は起点ペインと同じタブの中だけで、他のワークスペースや別のタブには触れない（`review` は worktree 側のタブが対象）。
- 同じタブに別の driver がいると、何もせずエラーで止まる。そのペインを閉じるか、別のタブから実行する。
- フォーカスは奪われないので、呼び出し元のペインに留まる。

`research` の `-n` は下限として扱われる。動いている researcher は読んだ内容の文脈を抱えているので、`-n` を小さくしても（付け忘れて既定の 2 になっても）減らない。足りない分だけ増える。減らすときはそのペインを手で閉じる。

`research` の調査役は driver の隣に2列で並ぶ。1人目が右半分を取り、2人目がそれを2列に割り、3人目以降は2つ前の調査役の下に入る。1列に積むと人数が増えるほど1つあたりが薄くなるが、このペインは眺めるものではなく読むもののため。

`research` は 4 並列以上で警告が出る。同じレート制限を共有するため、増やせば速くなるわけではない。

## 作業を割り振る

**やりとりは自分が立てたワーカーとだけ行う。** 宛先はこれで確定する。

```bash
herdr-agent-name coder
herdr-agent-name reviewer
```

`ListAgents` には他の driver のワーカーも同じ形の名前で並ぶ。接頭辞のペイン ID が自分のものと違えば別の driver の担当で、送れば無関係な文脈に割り込むことになる。

```
SendMessage(to: "wk-p3-reviewer", message: "...")
```

例外は `review` モード。ワーカーは新しく作った worktree のワークスペースにいて、そちらのペイン由来の名前を持つので接頭辞が違う。このときは起動時の出力の `AGENT` 列をそのまま使う。

`review` の1通目では `/code-review` を使うよう指示する。依頼文の型と、返ってきた指摘の扱いは `herdr-research` ではなく `herdr-review` が持つ。

- **1通目を自己完結させる。** ワーカーはこの会話の文脈を持っていない。対象のファイルやブランチ、判断基準、報告してほしい形式を書く。
- 返事は自動で届く。`ListAgents` を繰り返して待たない。終了だけ知りたいときは `notify_when_idle: true` を使う。
- `herdr agent prompt` は使わない。TTY への打ち込みになり、返事を画面から読み取ることになる。Claude 以外を起動したときだけそちらを使う。

## 注意

- 再実行しても自分のワーカーが再利用されるだけで、ペインは増えない。作り直したいときは先にそのペインを閉じる。
- 自分の権限で拒否された操作をワーカーに代行させない。ユーザーの許可判断を迂回することになる。
- 手で閉じてよいのは自分が作ったペインだけ。仕事が終わったら残すか閉じるかをユーザーに確認する。スクリプトがタブを整理するのはこの例外で、閉じたペインは出力に `closed` として並ぶ。
