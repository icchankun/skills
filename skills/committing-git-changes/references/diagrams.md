# 図の決まりと型

コミットメッセージやドキュメントに描く ASCII アートの図の決まり。図の記号は ASCII 文字だけで描く。罫線や矢印の記号（`─ │ ├ └ ► ▼`）は、環境によって幅が1にも2にもなるため（CJK 向けの設定のターミナルで `git log` を見たときなど）。全角の文字は幅が2になるので、揃える基準は行頭の空白の数だけにする。

## 揃える

- 1行は「空白 ＋ 記号1つ ＋ 文字」で書く
- 縦線と分岐の記号は、行頭から空白だけで数えられる列に置く。日本語や罫線のすぐ後ろの列に合わせない
  - `送信処理 -+-` のように、文字の後ろから分岐させない
  - 1行の中で `A -> B` とつなぐのはよい。縦に揃える必要がないため
- 字下げは半角2つずつにする。同じ深さのものは同じ列から始める
- 「変更前」「変更後」などのラベルは0列目に置き、中身は2つ字下げする
- 記号は次の組だけを使い、`→` `=>` などを混ぜない
  - つなぐ: `->`
  - 分岐: `|->`、`` `-> ``（最後の1つ）
  - 縦: `|`、`v`
- 変えたところには `（追加）` `（新規）` `（変更）` `（削除）` を付ける。前からあるものに印が要るときは `（既存）`

## 表を使わない

Markdown の表（`|`）も、`+--+--+` で組んだ表も使わない。列の位置が文字の幅に頼るので、全角が混ざるとずれる。項目を並べたいときは `ラベル: 値` の行を縦に並べる。

## 小さく保つ

- 図1つで話は1つにする。2つあるなら中見出しを分けて図も分ける
- 横は半角60字まで、縦は15行まで
- 箱（名前）は7個まで
- 箱の中は名詞か短い句にする。説明は図の外の補足に書く
- 変更前と変更後で変わらない部分は `...` で略す

## 型

描き方は次の3つだけにする。何を描くかではなく、どうつながっているかで選ぶ。

- 途中で分かれる: 分岐
- つながりが多い・行き来する: 1行に1つずつ
- 入れ子になっている: 構成

一列に進むだけの手順（画面の移り方、CI のジョブの順番、デプロイや埋め直しの手順など）は図にせず、番号付きの箇条書きにする。`|` と `v` で縦につないでも、番号より伝わることが増えず、行が3倍になるため。変えた手順には、箇条書きでも `（追加）` などの印を付ける。

```
1. 保存ボタンを押す
2. 入力を確かめる（追加）
3. 保存して一覧へ戻る
```

変更前と変更後を見せるときは、どの型でも「変更前」「変更後」のラベルを0列目に置き、中身を2つ字下げして上下に並べる。左右には並べない。

### 分岐

上から順に条件を見て、最初に当たったもので決まるときは、見る順に並べて最後に「それ以外」を置く。

```
通知
`-> 送り先の選択（追加）
    |-> メール送信
    |-> Slack 送信
    `-> プッシュ通知送信

通知を送るか
|-> 退会済み: 送らない
|-> 1時間以内に送った: 送らない（追加）
`-> それ以外: 送る
```

### 1行に1つずつ

状態の移り変わりや、ブラウザ・API・ジョブ・外部サービスのやりとりのように、つながりが多いものや行き来するものは、`A -> B: 何で・何を` を1行に1つずつ書く。やりとりは起きる順に上から並べる。

```
下書き -> 公開: 公開ボタン
公開 -> 非公開: 非公開ボタン（追加）
非公開 -> 公開: 公開ボタン（追加）

ブラウザ -> API: 記事を保存
API -> ジョブ: 通知を積む（追加）
ジョブ -> Slack: 通知を送る（追加）
API -> ブラウザ: 保存した記事
```

### 構成

罫線を使わず、字下げだけで入れ子を表す。ディレクトリ、設定ファイル、画面の部品の入れ子に使う。

```
skills/
  recording-browser-videos/（新規）
    scripts/
      record-scenes.sh
  recording-manual-checks/（変更）
```

テーブルとカラムの図は `templates.md` の「テーブルとカラムの変更」に従う。描き方は分岐の型と同じで、一列につながるテーブルだけは関係の多重度を書くために `|` と `v` で縦につなぐ。
