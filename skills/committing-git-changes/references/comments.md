# コードコメントの基準

ステップ3で、今回の差分で足した・変えたコメントに当てる。

コメントに残すのは、コードを読んでも分からないこと（なぜそうしたか、制約、外部仕様、ハマりどころ）だけにする

削るもの:

- コードをそのまま言い換えたもの（`# ユーザーを取得する` の下に `user = find_user`）
- 変更の経緯や作業メモ（`# 〜を修正`、`# 以前は〜だった`、`# 新しく追加`）。それはコミットメッセージに書く
- 関数名・引数名から明らかな内容を繰り返す docstring
- 区切りや飾りのためだけのコメント行
- 「重要:」「注意:」などのラベルだけで中身のない強調
- `humanizer-ja` の癖（大げさな言葉、念押し、翻訳調）を含むもの。残す場合も書き直す

短くするもの:

- 1行で言えることを複数行で書いている
- 同じ説明を複数箇所に書いている
