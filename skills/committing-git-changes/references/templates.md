# 種類ごとの型

型に当てはまる変更のときだけ使う。当てはまらない部分は無理に埋めず、見出しごと書かない。

## テーブルの追加

テーブル同士の関係を ASCII アートの図にする。足したもの・新しく作ったものには「（追加）」「新規」、前からあるものには「既存」と書く。関係の多重度（`1 : *` など）を矢印の横に書く。

````
### 🗃️ 記事とタグを紐づけるテーブルを追加

商品と同じく、記事ごとにタグを付けるテーブルと、おすすめに出すかのフラグを足しました

```
posts（記事、既存）
  featured: おすすめに出すか（追加）
  │
  │ 1 : *
  ▼
post_taggings（記事とタグの紐づけ、新規）
  post_id
  tag_id
  │
  │ * : 1
  ▼
tags（タグ、既存）
```

タグの追加・削除・入れ替えの操作も、商品と同じものを用意しています
````

- 似た既存のテーブルに倣った場合は、何に倣ったかを書く（「商品と同じく」）
- 用意した操作（追加・削除・入れ替えなど）を1文で書く

## API の追加

エンドポイントごとに、メソッドとパスを書き、レスポンスの形を json5 で書く。各フィールドの意味は行末のコメントに書く。

````
## 🔧 変更内容

下書き・非公開・公開日時の前の記事は返しません
商品の販売終了と同じく、公開期間が終わった記事も返しません

### ✨ 追加する API

`GET /api/posts`

```json5
{
  posts: [ /* 詳細と同じ形の記事 */ ], // 公開日時の新しい順。同じなら後に登録したものが先
}
```

`GET /api/posts/:slug`

```json5
{
  slug: "...",                // 記事の URL 用の識別子
  title: "...",               // 記事の題名
  published_at: "...",        // 公開日時
  cover_image: {              // 表紙の画像
    url: "...",               // 画像の URL
    width: 1200,              // 幅（px）
    height: 630,              // 高さ（px）
  },
}
```

画像を入れ子にしているのは、サムネイルなど別の大きさを足すときに同じ形で並べられるようにするためです
一覧はページを分けずに全件を返します
フィーチャーフラグが無効な場合は一覧も詳細も 404、公開中でない記事の詳細も 404 を返します
````

- 何を返さないか（絞り込みの条件）を先に書く
- 並び順は配列のフィールドのコメントに書く
- 形を決めた理由（入れ子にした理由など）と、ページ分け・エラー時の返し方を最後に書く
