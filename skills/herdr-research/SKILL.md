# herdr-research

researcher が調べ、まとめるのはこのペイン（起点なので `<ペインID>-driver` を名乗る）。ユーザーとやりとりするのは driver だけで、researcher 同士を会話させない。並列で走らせる意味が消え、往復がユーザーの画面にも出ない。

## ペインを確かめる

`ListAgents` を見る。宛先は**自分と同じワークスペースのワーカーに限る**。接頭辞はこれで取れる。

```bash
printf '%s\n' "${HERDR_PANE_ID%%:*}" | tr '[:upper:]' '[:lower:]'
```

ワーカーの名前は `<自分のペインID>-researcher-<番号>` で、`herdr-agent-name researcher-1` が宛先をそのまま出す。`ListAgents` に居なければ、`herdr-layout research -n <数>` でペインを立てるところからだと伝えて止まる。ここでペインを作らない。

`ListAgents` には他の driver のワーカーも同じ形で並ぶ。接頭辞のペイン ID が自分のものと一致するものだけが自分の担当。

## 問いを分ける

**先に問いを分けてから人数を決める。** 人数に合わせて問いを割ると、1人分の問いが薄くなるか、1つの問いが2人に跨る。

- **重ならないように分ける。** 同じファイルを2人に読ませても同じ答えが2つ返るだけで、レート制限は倍使う。
- **依存する問いを並列にしない。** 片方の答えが要るものは、順に回すか1人に両方持たせる。並列にすると、答えを知らないまま推測で埋めたものが返る。
- 分け方は層（呼び出し元 / 実装 / テスト・設定）か、対象（ディレクトリ、機能、フェーズ）で切ると重なりにくい。

分けた結果が1つなら、ワーカーを使わず自分で読む。1人に投げるのは往復が増えるだけになる。

## 依頼する

ワーカーはこの会話の文脈を持たない。1通目に**知りたいこと・探す範囲・返してほしい形式**を書く。

```
SendMessage(to: "wp-p1-researcher-1", message: "〈…〉がどこで呼ばれているかを調べてほしい。
探す範囲は app/services 配下。それ以外は見なくていい。
呼び出し箇所を file:line で挙げ、それぞれ何のために呼んでいるかを1行で添えてほしい。
分からなかったところは埋めずに『不明』と書いてほしい。
ファイルは編集しないでほしい。")
```

- **推測で埋めさせない。** 分からなかったと返ってくる方が、もっともらしい嘘より役に立つ。
- **根拠の形を指定する。** `file:line` を求めておくと、後で driver が自分で確かめられる。
- **範囲を書く。** 書かないとリポジトリ全体を読み始め、時間とレート制限を使う。

## まとめる

- **食い違いは多数決にしない。** 2人が同じことを言っても、同じ思い込みを共有しているだけのことがある。割れたら driver が該当箇所を自分で読んで決める。
- **根拠のない主張は採らない。** `file:line` が付いていない断定は、driver が確認するまで結論に入れない。
- **穴を埋め戻す。** 「不明」で返ってきたものは、放置するか、範囲を変えて投げ直すかを決める。黙って落とすと、調べたつもりの空白が残る。
- ユーザーへの報告は driver が1つにまとめて出す。誰が何を言ったかではなく、分かったこと・分からなかったことの形で書く。

## 規律

- **書き込ませない。** researcher は読むだけにする。全員が同じ作業ツリーで動くので、複数が書くとファイルを取り合う。
- 返事は自動で届く。`ListAgents` を繰り返して待たない。終了だけ知りたいときは `notify_when_idle: true` を使う。
- `herdr agent prompt` は使わない。TTY への打ち込みになり、返事を画面から読み取ることになる。
- 4人以上は同じレート制限を共有する。増やせば速くなるわけではない。
- 自分の権限で拒否された操作をワーカーに代行させない。ユーザーの許可判断を迂回することになる。
- 閉じてよいのは自分が作ったペインだけ。仕事が終わったら残すか閉じるかをユーザーに確認する。
