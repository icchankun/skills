# /handover

いまのセッションで積み上がった文脈を、引数で受け取った agent に `SendMessage` で渡す。

```
/handover <agent名>
```

宛先は `ListAgents` に出る名前（`wp-p2-driver` など）。**引数が無ければ渡さない。** 誰に渡すかが決まっていない引き継ぎは、書いても読まれずに残るだけなので、宛先を尋ねて止まる。

ファイルには書き出さない。渡す相手が決まっているときだけ渡す。

## ステップ1: 宛先を確かめる

`ListAgents` に指定された名前があることを確認する。

- 無ければ、その名前では送れないことを伝えて止まる。打ち間違いか、相手が既に終了している。
- Claude 以外（Codex, Gemini など）が相手で `ListAgents` に出ないときは `herdr agent prompt` を使う。TTY への打ち込みになるので、返事は画面から読み取ることになる。

## ステップ2: 作業状態を集める

以下を**並列**で実行:

```bash
git branch --show-current
pwd
git status --short
git log --oneline -10
```

## ステップ3: 引き継ぎを組み立てる

会話履歴から整理する。**「なぜそうしたか」を最優先で残す。** 何をしたかはコミットとファイルに残っているが、なぜそうしなかったかはこの会話にしか無い。

1. **タスク概要**: 取り組んでいたこと（チケットURL含む）
2. **完了した作業**: コミット単位で
3. **未完了の作業**: 残タスク、ファイルパス
4. **意思決定の記録**: 設計判断とその理由
5. **捨てた選択肢と理由**: 同じ検討を相手に繰り返させないための最重要項目
6. **ハマりどころ・学び**: エラー、詰まった点、得た知見
7. **ブロッカー**: 進行を妨げているもの
8. **次のアクション**: 相手が最初にやること

## ステップ4: 送る

**相手はこの会話を持っていない。1通で完結させる。**

- **ブランチと worktree のパスを必ず書く。** 相手は別の worktree にいることがあり、同じ `git status` を打っても同じものは見えない。
- 未コミットの変更があるなら、それがどのツリーにあるかを書く。相手の手元には無い。
- 会話の要約を貼るのではなく、相手がそのまま動ける形にする。

```
SendMessage(to: "wp-p2-driver", message: "〈…〉の作業を引き継いでほしい。

## 対象
ブランチ: feature/foo
worktree: /path/to/worktree

## ここまで
- 〈…〉（コミット abc1234）

## 残り
- 〈…〉（app/models/foo.rb）

## 決めたこと
- 〈…〉にした。理由は〈…〉

## 捨てた選択肢
- 〈…〉は〈…〉のため採らなかった

## 次にやること
1. 〈…〉")
```

## ステップ5: 報告する

- 誰に何を渡したかをユーザーに伝える。`SendMessage` の往復はユーザーの画面に出ない。
- 相手からの返事は自動で届く。`ListAgents` を繰り返して待たない。
