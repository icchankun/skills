# planning-manual-checks

レビュアーが画面上で手で確かめる項目を、撮影と PR より先に決める。動画はこの項目に沿って撮り、PR にも同じ項目を載せる。

## 1. 項目を書く

差分から画面上に現れる挙動を読み取り、「どこで何をすると、どうなるか」が分かる粒度で書く:

```markdown
- [ ] ログイン画面でメールアドレスを空のまま送信すると、入力欄の下にエラーメッセージが表示される
- [ ] 正しい認証情報でログインすると、ダッシュボードへ遷移する
- [ ] セッション切れの状態で操作すると、ログイン画面へ戻される
```

自動テストで検証済みの内容は書かない。書くほどチェックリスト全体の密度が下がるため。

画面に現れる変更がない場合（内部リファクタ、CI設定の変更等）は、確認項目は無理に作らず、「UI上の変更なし」と1行で書いて 2 は飛ばす。

## 2. 過不足を確かめる

サブエージェント（Agent ツール、`model: sonnet`）に、差分・変更に関係するテスト・1 の項目を渡し、次の3つを返してもらう。なければ「なし」とする。

- 足りない: 画面に出る変化があるのに、項目にないもの
- 余分: 自動テストで確かめ済みのもの、画面では見えないもの
- 曖昧: どの画面で何をするかが書かれておらず、その通りに操作できないもの

返ってきたものを直す。書いた本人は差分を読んだ順に項目を拾うので、拾い漏れに気づきにくいため。

## 3. 書く

`reviewing-writing` で見直した項目を、dev-flow.md の「動作確認」の節に書く。なければ結果として返す。
