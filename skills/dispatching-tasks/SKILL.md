# dispatching-tasks

指令役は、作業を受け取って worktree に渡すところまでを受け持つ。実装はしない。

## 手順

1. **チケットを読む。** リンクがあれば中身を読み、要件・受け入れ条件・関連するリンクを拾う。曖昧な点があれば、ここでユーザーに聞く。渡した後に聞き直すより早い。
   - 「なぜ」（背景・課題・対応方針）もここで決める。チケットに書いてあれば、それを見せて合っているか確かめる。なければ聞く。自明なら聞かない。なぜはエージェントが考えるものではなく、人間が決めるもののため。
2. **ブランチと worktree を作る。** `creating-git-branches` を呼ぶ。
   - Herdr.app の中なら、`git wt` のフックが worktree を Herdr.app の space として開き、最初のタブで Claude を driver として起動する。フックの出力に `driver: <agent名>` が出る。
   - 出なければ、`herdr-app ls` で folder が worktree のパスと一致する space を探し、その最初の terminal の番地に `-driver` を付けた名前を使う（`t12` なら `t12-driver`）。
3. **引き継ぐ。** `handover <agent名>` を呼ぶ。引き継ぎには次を入れる。
   - チケットの URL と、1 で拾った要件・受け入れ条件・なぜ
   - 決めたこと、聞いて答えをもらったこと
   - 最初にやること: `/running-dev-flow` を実行する
4. **手を離す。** 誰に何を渡したかをユーザーに伝えて終える。以降のやりとりは、引き継いだ先のペインで行う。

## Herdr.app の外にいるとき

`HC_TERMINAL_ID` がなければ、driver は立たない。worktree のパスを伝え、そこで新しいセッションを開いて `/running-dev-flow` を実行するよう伝えて終える。

## 規律

- 実装しない。指令役のセッションに実装の文脈を積むと、引き継ぐ量が増え、二重に作業が進む。
- 引き継ぎ先が見つからないまま `handover` しない。宛先のない引き継ぎは読まれない。
