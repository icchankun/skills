# recording-browser-videos

ブラウザの操作を、場面ごとに撮ってつなぐ。見た目の部品はスクリプトに固定してあるので、撮るたびに書くのは場面ごとの数行だけになる。

依存: `playwright-cli`、`ffmpeg`（どちらも mise で入れる）

`playwright-cli` の書き方は `playwright-cli` skill に従う。読むのは SKILL.md と、使う資料（`references/video-recording.md`・`references/storage-state.md`）だけにする。全部読むとトークンが多くかかるため。食い違うときは `playwright-cli <コマンド> --help` を正とする。

## ブラウザの扱い

スクショ（capturing-screens）と動画のどちらも、この決まりに従う。

ブラウザは worktree ごとに1つだけ立て、使い終わったら必ず閉じる。コマンドが終わっても `close` を呼ぶまで裏で動き続けるので、閉じ損ねたブラウザが worktree の数だけ残ると、録画を続けたまま CPU とメモリを使い切る。

- セッション名は `capture-<worktree の名前>` にする。worktree ごとに別のブラウザになり、ほかの worktree の撮影と取り合わない。
- headless で起動する（`--headed` を付けない）。headed のブラウザは放っておいても止まらないため。
- 画面サイズは headless の初期の 1280×720 のまま撮り、`resize` しない。変えると動画の下に灰色の帯が出る。
- `open` には `--idle-timeout=600000` を付け、閉じ損ねても10分で止まるようにする。
- 操作はシェルのスクリプトにまとめて Bash の1回の呼び出しで動かし、先頭で `trap '… close' EXIT` を仕掛けて、どう終わっても閉じる。1操作ずつ呼ぶと、呼び出しの数だけ待ち時間とトークンがかかるため。
- `playwright-cli` は、置き場所のディレクトリで動かす。今いるディレクトリに `.playwright-cli/` を作るので、worktree で動かすと未追跡のファイルが残る。
- 押す場所は、先に1回だけ `snapshot` で調べ、`'text=保存'` や `'role=button[name="保存"s]'` のようなロケーターで書く。role の name は二重引用符で囲み、末尾に `s` を付けて完全一致にする。囲まないと空白を含む名前で失敗し、`s` がないと「完了」が「未完了」にも当たる。snapshot の `e12` のような参照は、開き直すと変わるので使わない。

### ログインの状態

ログインが要る画面は、1回ログインしたら `state-save` で状態を残し、次からは `open` のあとに `state-load` する。ファイルは worktree の git dir に置く。`git wt -D` で worktree と一緒に消える。

```bash
auth="$(git rev-parse --absolute-git-dir)/browser-auth.json"
playwright-cli -s="$session" state-save "$auth"   # ログインしたあと、1回だけ
playwright-cli -s="$session" state-load "$auth"   # 次から
```

- 手元の開発用のアプリなら、seed や README にある開発用のユーザーで、ログインの画面をスクリプトで操作してログインする。人の手は要らない。
- SSO や2段階認証があってスクリプトでログインできないときだけ、`--headed` で開いてユーザーにログインしてもらい、`state-save` したらすぐ閉じる。パスワードやコードを Claude が扱わない。
- 撮っている途中でログインの画面に飛ばされたら、状態の期限が切れている。もう一度ログインして保存し直す。

## 1. 場面ごとのスクリプトを書く

場面ごとに `<場面の置き場所>/<番号>.sh` を書き、動画も場面ごとに撮って番号の順につなぐ。直した場面だけを撮り直せるため。

```bash
# <場面の置き場所>/3.sh
TITLE="チェックを付けると、件数が「1 件」になる"   # 札と右上の見出しに出す題。30字くらいまで
SUBTITLE="期待: 取り消し線が付き、ヘッダーが「1 件」"  # 札に添える1行（省いてよい）

# 録画しない前準備。前の場面の結果に頼らず、この場面だけで撮れるようにする
setup() {
  fill_text "やること" "牛乳を買う"
  P click 'role=button[name="追加"s]'
}

# 録画する操作
steps() {
  zoom 'main'
  click_on 'role=checkbox[name="牛乳を買う を完了にする"s]'
  expect_text "1 件"
}
```

題には番号を付けない。場面の順番が変わったときに、動画とほかの資料の番号が食い違うため。`setup` を省いた場面は、開いたページからそのまま撮る。

スクリプトの中では、同梱の `scripts/lib.sh` の部品を使う。

| 部品 | すること |
|---|---|
| `click_on '<ロケーター>'` | 押す要素をスポットライトで照らし（まわりを少し暗くし、要素を藍色の光る枠で囲む）、同時にカーソルを動かして押す。押すとスポットライトは消え、押した点から輪が広がり、押した要素とカーソルが少し沈む |
| `type_text "<欄の名前>" "<値>"` | 入力欄をスポットライトで照らしたまま、1文字ずつ打つ。打ち終えたらスポットライトは消える。何を入れたかが動画で見える |
| `select_option '<ロケーター>' "<表示されている文>"` | セレクトボックスをスポットライトで照らし、選ぶ |
| `expect_text "<文>" [ミリ秒]` | 期待する文が画面に出るまで待ち（既定は5秒）、出たらその文を文字の幅に合わせてスポットライトで照らし、少し見せる。出なければ「不具合の疑い」と出して止まる |
| `spot '<ロケーター>' [ミリ秒]` | 文以外で見てほしい場所（件数の表示・追加された行など）をスポットライトで照らし、少し見せる（既定は900ミリ秒） |
| `zoom '<ロケーター>' [倍率]` | 対象を画面の中央に寄せて拡大する（0.5秒。ゆっくり動き出してゆっくり止まる）。倍率を省くと、対象が画面の8割に収まる大きさ（2倍まで）になる |
| `unzoom` | 拡大を戻す。場面の途中で別の場所を見せるときに使う。`steps` の最後では要らない（次の場面はページを開き直す） |
| `scroll_to '<ロケーター>'` | 対象までなめらかにスクロールする。押す・打つ・選ぶ部品は、見えていなければ自分でスクロールするので、見せるだけのときに使う |
| `goto "<URL>"` | ページを移る。カーソルと右上の見出しは、移った先でも出し直される。リンクを押して移ったときも同じ |
| `hold [ミリ秒]` | 結果が見えるまで止める（既定は700ミリ秒） |
| `fill_text "<欄の名前>" "<値>"` | 入力欄に一度に入れる。`setup` の前準備で使う |
| `P <コマンド>` | `playwright-cli` をそのまま流す。出力はログに残し、失敗したらその末尾を出して止まる。部品にない操作と、`setup` の前準備で使う |

- どの部品も playwright-cli の呼び出し1回にまとめてあり、1回に約0.7秒かかるので、部品にある操作は `P` で組み立て直さない。
- `steps` で押すときは、`P click` ではなく `click_on` を使う。`P click` ではスポットライト・カーソルの移動・押した印がどれも出ない。録画しない `setup` では `P click` でよい。
- playwright-cli の枠（`video-show-actions --highlight-style`）は使わない。playwright は hover と click で別々に、しかもマウスを動かす前に枠を出すので、枠が2回点滅してからカーソルが動いて見える。
- スポットライトは、そのとき見てほしい場所に当てる。操作する前は押す・打つ場所に、操作したあとは結果が出た場所に当てる（`expect_text` か `spot`）。押す場所のスポットライトは押した瞬間に消え、札は操作を始める前に消えるので、結果は隠れない。動きを足すときも、結果を見せる時間と場所を削らない。
- 1つの場面に操作が複数あるときは、`steps` に順に並べる。

### 拡大する範囲

`zoom` には、操作する要素と、その結果の出る場所が両方入る要素を渡す。結果が拡大の外に出ると、何が起きたか見えない。

- 入力欄とその下のエラーなら、両方を含むフォームや親の要素を渡す。倍率は省いて自動にする。数字で決めると、横に長い要素の端が画面からはみ出る。
- 結果がヘッダーなど、操作する場所から離れたところに出る場面では `zoom` を使わない。
- `zoom` は `body` を CSS で大きくするので、`position: fixed` や `sticky` のヘッダーは位置がずれたり画面の外に出たりする。ヘッダーの中身を見せたい場面では使わない。

## 2. 撮ってつなぐ

worktree の中から、同梱の `scripts/record-scenes.sh` で撮る。場面ごとに、ブラウザを開く → `setup` → 札を出す → 録画を始める → 札を約1秒見せて消す → `steps` → 録画を止める → mp4 にする、を流す。動画は札から始まり、末尾の止まった部分は切るので、場面のあいだに間が空かない。

```bash
~/.claude/skills/recording-browser-videos/scripts/record-scenes.sh -j 4 <場面の置き場所> "<URL>" <出力.mp4>     # 全部
~/.claude/skills/recording-browser-videos/scripts/record-scenes.sh -j 4 <場面の置き場所> "<URL>" <出力.mp4> 3   # 3 だけ撮り直す
```

```
全部撮る
  1.sh -> 1.mp4 --+
  2.sh -> 2.mp4 --+--> 番号順につなぐ --> 出力.mp4
  3.sh -> 3.mp4 --+

3 だけ撮り直す
  1.mp4 (前のまま) --+
  2.mp4 (前のまま) --+--> つなぎ直す --> 出力.mp4
  3.sh -> 3.mp4 (新) +
```

- ログインの状態を残したファイルがあれば、場面ごとのブラウザが読み込んでから撮る。同時に撮るときも、1回ログインしておけば場面ごとにログインし直さなくてよい。
- `-j` で、場面ごとに別のブラウザを立てて同時に撮る。全体の時間が、ほぼいちばん長い場面1つ分になる（3場面で31秒が11秒になった）。場面どうしがサーバーのデータ（同じユーザーの一覧など）を取り合うときは `-j` を付けず、1つずつ撮る。
- 撮った場面の動画とスクリプトは、場面の置き場所に残る。画面が変わったら、変わった場面のスクリプトだけを直して撮り直す。
- 最後に `DONE` が出なければ途中で止まっている。エラーを見て直し、止まった場面だけを撮り直す。録画の途中で失敗した場面は、動画が残らない。

動画は 1280×720・24fps の H.264 の mp4 にする（CRF 28）。webm より軽く、Safari でも再生できる。字がにじんで読めなければ、`record-scenes.sh` の `-crf 28` を 23 まで下げて撮り直す。

## 見た目の部品

playwright-cli の飾り（枠・操作の名前・カーソル）はどれも切り、自前の部品を出す。見た目は `scripts/decor.js`（カーソル・押した印・右上の見出し・スポットライト）と `scripts/lib.sh`（札・ズーム）に固定してあるので、変えるときはそのファイルを直す。

- カーソル: 白く縁取った黒い矢印。playwright のカーソルは見た目を変えられないため、自前のものを描く
- 押した印: 押した点から細い輪が広がり、押した要素とカーソルが少し沈む
- スポットライト: 見てほしい場所（押す・打つ・選ぶ場所と、操作の結果）のまわりを少し暗くし、藍色の光る枠で囲む
- 札: 画面をぼかして少し暗くした上に、題と添え書きの白い札を浮かせる
- 見出し: 右上に今の場面の題を出し続ける。動画の再生バーで隠れないよう、下には置かない
- ズーム: ゆっくり動き出してゆっくり止まる。0.5秒

## 規律

- 本番や共有の環境を撮らない。手元で起動したアプリだけを撮る。
- 撮った動画に、個人情報や秘密の値が写っていないかを見る。写っていたら、ダミーのデータで撮り直す。
